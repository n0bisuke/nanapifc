## 機能3: 調整さん複数URL対応(Phase A・完成)

`docs/ROADMAP.md` の Phase A。調整さんURLを複数運用できるようにする基盤整備。

1. **設定**: `CHOUSEISAN_URL` をカンマ区切りで複数URL指定できるようにした
   (`src/config.ts` の `chouseisanUrls: string[]`。`splitUrlList` で分解し、空白・空要素は除去)。
   単一URLのSecret値もそのまま動く(後方互換)。
2. **取得**: `src/chouseisan.ts` に `fetchChouseisanAll` を追加。
   複数URLを順番に取得し、リクエスト間隔(`REQUEST_INTERVAL_MS`, デフォルト500ms)を空ける。
3. **古い出欠表の自動除外**: `partitionUpcoming` で「未来の日程を1つも持たない出欠表」を
   除外(当日を含む未来の日程があれば残す)。消し忘れても害が出ない。
   除外されたものはログに出す(`調整さん「…」: 未来の日程がないためスキップします`)。
4. **出欠カレンダーへの統合**(URLをまたいで冪等):
   - 出欠付きカレンダーに載せる対象判定は全出欠表のスロットをマージしたものに対して行う
   - 説明欄は出欠表ごとにブロック(`調整さん「名」(回答N名)` + スロット行)。
     単一URLなら従来と全く同じ形式
   - タイトルの `調整N名○` のNは、その日に複数出欠表が候補を持つ場合は最多の○人数
   - 単独日程の全天候イベントは `chouseisanId = {出欠表ID}:{スロット番号}` で
     出欠表ごとに一意なので、複数URLでも衝突しない
   - 削除判定の keep も全出欠表分を渡し、古い出欠表のイベントは自動削除される
5. **テスト**: `splitUrlList` / `partitionUpcoming` / `attendanceDescription` のテストを追加。
   27 → 38テスト、typecheck・全テスト緑。dry-runでLaBOLA取得の実働確認済み
   (調整さんURLはSecretsのみのため、ローカルでは出欠部分は検証対象外)。

## 調査・決定事項

  (合計だと同一メンバーの二重計数の恐れがあるため)
- Phase B(LINEでのURL自動検出)に進む場合、Secretの `CHOUSEISAN_URL` を

## 運用対策: publicリポジトリのscheduled workflow自動無効化

- GitHubの仕様: publicリポジトリは60日間アクティビティがないとscheduled workflowが
  自動無効化される → 毎時のsyncが止まる恐れ
- 対策として `.github/workflows/keepalive.yml` を追加:
  2週間ごとに動き、**最終コミットから30日以上経過している場合のみ**空コミットで
  タイマーをリセット(開発が活発な時期はコミットを積まないので履歴は汚さない)
- 無効化された後はActionsページから手動再有効化するか、cron定義を変えるコミットで
  再活性化できる(仕様上、bot自身が自分を再開することはできないため予防が主眼)
